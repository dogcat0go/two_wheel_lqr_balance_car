# 知识自测：验证"AI 写的代码"是否变成了"我的知识"

适用范围：本仓库阶段 0~3 已落地的内容（频带分离、安全层、姿态估计、平衡状态反馈）。
阶段 4/5 落地后按同样格式往题库里补题。

核心问题：AI 可以替你写代码，但替不了你**在实验前下判断**。
所以整套自测的重心不是"能不能看懂代码"，而是"能不能在动手前预测物理系统的行为"。

---

## 一、能力分级与总体判定

| 层级 | 名称 | 判据 | 考察方法 |
|------|------|------|----------|
| L1 | 复述 | 能说出代码做了什么 | 不单独考（AI 辅助下人人能过） |
| L2 | 因果解释 | 不看注释能回答"为什么这样写、不这样会怎样" | 方法一：闭卷题库 |
| L3 | 反事实预测 | 改动前能预测系统行为，方向与数量级都对 | 方法二：预测-验证日志 |
| L4 | 重建/迁移 | 不看原码重写核心模块，首次上机基本正确 | 方法三：盲重建 |

**总体判定**（三项独立，不能互相抵扣）：

- L2 过关：题库得分 ≥ 8 / 12
- L3 过关：连续 20 次实验预测命中率 ≥ 70%
- L4 过关：三个盲重建任务全部通过验收

建议节奏：L2 随时可做（每次约 40 分钟）；L3 融入日常调车，攒够 20 条记录即可判定；
L4 找一个整块时间（半天）集中做。三项都过，才能说"掌握了当前项目"。

## 二、方法一：闭卷题库（考 L2）

### 规则

1. **闭卷**：不看代码、不看注释、不问 AI。允许在纸上画图推导。
2. 每题按三档打分：
   - 0 分：说不出，或方向说反
   - 0.5 分：能说个大概，但机制或数量级含糊
   - 1 分：机制说得清，涉及数字的能给出正确数量级
3. 答完后对答案（每题标注了出处），把 0 分和 0.5 分的题记入"待补清单"。
4. 隔两周重测一次，**只重测上次没拿满分的题**。同一题连续两次满分才算真正掌握。

## 三、方法二：预测-验证日志（考 L3，含金量最高）

### 规则

1. 每次上机改参数/改逻辑之前，**先把预测写进日志再动手**。事后补写的不算。
2. 预测必须包含**方向**和**数量级**两部分，只写"会变差"这种不可证伪的话不算一条记录。
3. 命中判定：方向对 + 数量级对（误差在 3 倍以内）= 命中；方向对但数量级差很远 = 半中；方向错 = 未中。
4. 命中率 = (命中 + 0.5×半中) / 总条数。**连续 20 条 ≥ 70%** 即 L3 过关。
5. 未中的记录最有价值：必须写"偏差原因"，这一栏空着的记录作废。

### 日志模板（建议直接建 `docs/prediction_log.md` 累积）

```
### 记录 N（日期）
改动:     （如：d 0，把 k_θ̇ 清零）
预测:     （如：失去阻尼项，车会在平衡点附近以约 λ/π ≈ 9~10Hz 量级振荡发散，2s 内触发 FALL）
实际:     （贴关键遥测行）
判定:     命中 / 半中 / 未中
偏差原因: （未中/半中必填）
```

### 实验题源（按需取用，也可自拟）

难度递进，先做 ①②③ 这类安全的，做 ⑦⑧ 前想清楚失败模式：

1. `f 20` 压遥测周期后，用 `d 0` 观察纯 P 控制的振荡频率——先算后测
2. `t` 拧平衡角 ±1°，预测稳态 effort 和 pitch 残差的变化方向与大小
3. `i` 从 0 加到某值，预测积分项消 trim 残差需要几秒（结合 kIntegTermLimit=15）
4. `p` 按 ×1.5 爬升时，预测出现高频抖振前 k_θ 大概能到多少（结合 730 上限的推导）
5. 把 `kPitchGyroCoef` 改 0.5 重新编译，预测静置和手扶晃动两种工况下 pitch 曲线的差异
6. 把 `kSpeedLpfAlpha` 改 1.0（不滤波），预测遥测里 v 的表现（阶段 3 不影响平衡，为什么？）
7. 把 `kCtrlHz` 降到 50，预测还能不能平衡、临界现象是什么（做前想好：架空测试）
8. `x` 模拟断链后再 `o` 恢复，预测平衡模式下恢复流程需要哪几步、漏一步会怎样

### 反作弊约定

预测阶段可以查教科书、查自己以前的推导，但**不可以问 AI**。
问了 AI 的记录标记为"辅助"，不计入命中率统计。

## 四、方法三：盲重建（考 L4）

### 规则

1. 新建临时目录，不看本仓库任何源码和文档；只允许查芯片/库的官方 API 文档。
2. 写完先自查一遍再编译。记录三个数字：**总耗时、编译报错轮数、与原版行为不一致的点数**。
3. 对照原码 review 时，把"原版有而我漏掉的语义"逐条列出——这份清单就是你的知识缺口清单。

### 任务与验收标准

**任务 1：BalanceController（参考原版约 60 行，限时 2 小时）**

必须覆盖的语义（对照 `BalanceController.cpp` 验收）：

- [ ] 统一状态反馈：4 个比例项 + 1 个积分项，误差 = 状态 − 参考
- [ ] 条件积分抗饱和：饱和 **且** 误差同方向时冻结积分（两个条件缺一不可）
- [ ] 积分项单独限幅（integ_abs）与总输出限幅（out_abs）是两层
- [ ] ki 为 0 时积分状态清零（避免残留）
- [ ] reset() 清积分与分量；分量数组供遥测定位"哪一项在振荡"

**任务 2：互补滤波 pitch 估计（限时 1 小时）**

- [ ] 写出滤波公式，说明系数的物理意义
- [ ] 说清两个传感器各自的失效模式：陀螺（漂移）、加速度计（振动/线加速度污染）
- [ ] 说明为什么 pitch_rate 直接取陀螺而不做任何滤波
- [ ] 说明零偏标定为什么必须静止、必须在控制环启动前完成

**任务 3：Safety 层（参考原版约 80 行，限时 2 小时）**

必须覆盖的语义（对照 `Safety.cpp` 验收）：

- [ ] 三类故障位掩码：FALL / IMU_LOST / CMD_TIMEOUT，可同时置位
- [ ] 时间戳年龄用有符号比较（跨核/跨 ms 边界 stamp 可能略新于 now）
- [ ] 摔倒判定去抖：连续超角 hold_ms 才置位，回到角度内即清计时
- [ ] 锁存语义可开关：平衡模式锁存（必须显式清除），开环模式自恢复
- [ ] limit()：故障时输出清零**且复位斜率限幅状态**（漏了这条，解锁瞬间会从旧值跳变）
- [ ] 饱和在前、斜率限幅在后，每轮独立维护 last_out

### 通过标准

三个任务全部满足：编译报错 ≤ 2 轮、语义清单漏项 ≤ 1 条/任务、限时内完成。
任何一个任务漏项 ≥ 3 条，说明该模块目前只是"看懂过"，两周后重做该任务。

### 最终自检（阶段 3 收官时问自己一句）

不看 `config.h`，能否独立复现这条推导链：

> 质心到轮轴 l ≈ 12mm → λ = √(g/l) ≈ 30 rad/s → 倒塌特征时间 ≈ 33ms
> → 设计点 ω_n = 2λ、ζ = 0.8 → T_d = k_θ̇/k_θ ≈ 0.022s
> → 斜率限幅、摔倒去抖、控制频率的取值全部由这条链约束

能，阶段 3 的知识就是你的；不能，缺口就在断掉的那一环。
