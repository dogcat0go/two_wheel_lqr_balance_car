# 阶段 4 速度环 / 位置环调参记录

> 目标：在阶段 3 姿态环基础上，消掉「站得住但持续单向漂移」，并能接受速度指令。
> 过关标准（`docs/Sim2Real_list.md` 阶段 4）：定点站立不漂移；给 `v` 能匀速前进/后退，
> 撤销后停回原地附近；复现/排掉仿真里的「停车倒退、来回振荡」。
>
> **不新建文件、不新开任务、不做级联**——只在现有 200Hz 单环状态反馈里多两项增益。
> 依据见 [`Sim2Real_list.md` 阶段4](Sim2Real_list.md)。
> \(k_{\dot s},k_s\) 初值/范围理论见 [`stage34_gain_init_theory.md`](stage34_gain_init_theory.md#stage4)；
> 「姿态环 alone 必漂」见 [`balance_gain_theory.md` §9](balance_gain_theory.md#pitch-only)。

---

## 为什么阶段 3 会单向漂移 {#why-drift}

姿态环单独在数学上不可能渐近稳定：把「摆 + 电机一阶滞后」写成 \([\theta,\dot\theta,v]\)
三阶模型，\(k_\theta\) 在特征多项式里精确抵消，常数项恒 \(<0\)，必有一个正实根
（推导见 [理论 §9](balance_gain_theory.md#pitch-only)）。物理含义：扶直的代价是轮子
朝一个方向持续加速，没有速度反馈就没有东西把 \(v\) 拉回来。

阶段 4 补的这一项 \(k_{\dot s}(v-v_{\mathrm{ref}})\) 正是那个"拉回来"的力。

---

## 控制律：还是同一个式子，多两项 {#law}

\[
u = k_\theta e_\theta + k_{\dot\theta}\dot\theta
  + \underbrace{k_s (s-s_{\mathrm{ref}})}_{\text{位置}}
  + \underbrace{k_{\dot s}(v-v_{\mathrm{ref}})}_{\text{速度}}
  + k_{i\theta}\!\int e_\theta\,dt
\]

阶段 3→4 唯一变化是 \(k_s,k_{\dot s}\) 从 0 打开、\(s_{\mathrm{ref}}/v_{\mathrm{ref}}\) 由指令给。
控制环结构、频率、任务划分**全不动**，与阶段 5 LQR 的 \(u=-Kx\) 仍然同构。

### 位置设定点跟随速度积分（关键）{#pos-ref}

`control_task` 里 `pos_ref` 每拍按速度指令积分：

```text
balancing:  pos_ref += v_ref * dt          // 匀速巡航时位置误差不累积
otherwise:  pos_ref  = 当前位置             // 使能/故障时锁零点，解锁从零误差起步
```

不这么做的后果：给了 `v` 让车前进，位置项 \(k_s(s-s_{ref})\) 会因为 \(s\) 一直增大而
反向拉，和速度项对着干，表现为「想走走不动 / 走一段被拽回来」。这就是计划里提的
`x_ref 锁存`。当 \(k_s=0\)（阶段 4 第一步）时 `pos_ref` 不参与，无副作用。

## 参数与接线 {#params}

`include/config.h`：

| 参数 | 值 | 单位 | 说明 |
| --- | ---: | --- | --- |
| `kGainVel` | 0（起步 40） | %/(m/s) | \(k_{\dot s}\)，**先调这个** |
| `kGainPos` | 0 | %/m | \(k_s\)，站稳后再加做定点 |
| `kMaxLinearMps` | 0.4 | m/s | 速度目标限幅，防手滑 |

上电默认 `kGainVel=kGainPos=0`，行为与阶段 3 **完全一致**；靠串口在线拧，定稿写回。

> **前置硬指标**：`kMPerTick` 必须已按当前轮/编码器重标（见 `config.h` 的 TODO）。
> 阶段 3 只用 pitch 不受影响，但阶段 4 速度反馈直接吃这个值，标歪了增益就调歪。
> 验证：手推车走 1.00 m，看遥测 `v` 积分/位置变化是否接近 1.00 m。

### 串口命令（新增）{#cli}

| 命令 | 作用 |
| --- | --- |
| `w <v>` | 设 \(k_{\dot s}\)（`kGainVel`） |
| `y <v>` | 设 \(k_s\)（`kGainPos`） |
| `v <mps>` | 速度目标，`kMaxLinearMps` 限幅；`s` 或断链清 0 |

遥测行已扩展出全部五个分量，判断是哪一项在振：

```text
m=1 hz=200 ovr=0 fault=0x00 | pitch=2.71 ref=2.70 deg rate=0.01 |
u pit=0.3 rate=0.1 pos=0.0 vel=-2.1 int=0.0 | vref=0.000 v=-0.031/-0.029 eff=-1.7/-1.6%
```

`u pos=/vel=` 就是位置/速度项对占空比的贡献。

车先架空做 Step 0，之后落地。全程 `m 1`，沿用
[`tools/stage2_serial_bridge.py`](../tools/stage2_serial_bridge.py) 收发分离 + 落盘，
判振荡先 `f 20`。

### Step 0：速度反馈符号（开环，必做）{#step0}

倒立摆的速度反馈是**正**的（k_vel>0）：车前冲要先驱动更快、把车身扳后仰再刹住
（非最小相位）。所以关键不是 `u vel` 的方向，而是 **speed 与 effort 必须同号**。

开环测：`m 0`、`e 15`。车朝 +effort 方向走，看遥测 `v`：

- [ ] `v` 为**正** → speed 与 effort 同号，正确
- [ ] `v` 为**负** → speed 极性反了，正的 `kGainVel` 会变正反馈，**给越大越发散**

反了不要动 `kWheelDir`（那会连 effort 一起翻、破坏平衡），而是单独翻编码器方向。
已确认同号（本车 e>0 → v>0）方可进 Step 1。

## 现象 → 排查 {#troubleshoot}

| 现象 | 首查 |
| --- | --- |
| 仍单向漂移 | \(k_{\dot s}\) 太小，或 `kMPerTick` 没重标导致速度反馈太弱 |
| **开 `k_vel` 后变成恒定单向缓慢爬行** | **不是故障，是 trim 残差显形**，见 §{#kvel-drift} |
| 前后来回抖动 | 位置环欠阻尼 / 死区极限环，走 §{#shake} 的隔离流程 |
| 给 `v` 走不动 / 被拽回 | `pos_ref` 未随速度积分，或 \(k_s\) 太大压着，见 §{#pos-ref} |
| 停车倒退 | 速度项符号（Step 0），或 `pos_ref` 在停车瞬间没锁住 |
| 一开 `k_vel` 就飞（越大越快发散） | speed 与 effort 反号，Step 0 没通过 |

### 开 `k_vel` 后恒定爬行 = trim 显形 {#kvel-drift}

`k_vel=0` 时 trim 残差 δ 让车持续加速（被死区/摩擦压成"轻微移动"）；开了 `k_vel`
把无界加速收成**有界恒速漂移**：

\[
v_{ss}=\frac{k_\theta\,\delta}{k_{\dot s}}
\]

所以这是速度环**在正常工作**、把病灶显形，不是它把车弄坏。三条推论：

- 漂移**方向** = trim 偏的方向 → 拿它当 trim 校准的指针（Step 3 那步）
- \(k_{\dot s}\) 越大漂移越慢（反比），但光靠加大 `k_vel` 治标不治本
- 根治：① `t` 修 trim 让 δ→0；② 加 `k_pos`，把恒速漂移变成一个固定的小站立位置偏移
  \(s_{ss}=k_\theta\delta/k_s\)（车真正停住）

### 前后来回抖动的隔离流程 {#shake}

理想 `w=40+y=10` 是 ζ=1.0（不该抖），现实里速度 LPF ~15ms 滞后 + 死区吃掉阻尼，
位置慢模态变欠阻尼。**先隔离再定向调**：

1. `f 20` 提高遥测率，看周期与哪一项在摆：
   - 周期 1~2s、`u pos=`/`u vel=` 大幅摆 → 位置环（最常见）
   - 周期 <0.5s、`u pit=`/`u rate=` 在抖 → 速度噪声/俯仰环
2. `y 0` 暂时关位置环：
   - 抖停、只剩缓慢漂移 → 确认位置环，走 A
   - 仍抖 → 速度噪声，走 B

**A. 位置环欠阻尼**——顺序不能反（trim 没修好，位置环要扛大偏移、反复穿死区，抖更凶）：

```
y 0          # 先关位置环
t <±0.2°>    # 盯 v 把稳态漂移调到最小
y 5          # 从 5 起，不要直接 10；能定住再往上 8/10
```

还抖就**加阻尼**：`w 60`（`k_vel` 是位置模态的阻尼器，`w`↑ 或 `y`↓ 都提高 ζ）。
口诀：**抖 = 阻尼不够 → 降 `y` 或升 `w`。**

**B. 速度噪声**（关了位置环还抖）：`w 20` 降速度增益，或加强滤波
（`config.h` 的 `kSpeedLpfAlpha` 调小、`kSpeedDiffWindow` 加大）。

**现实预期**：平衡 effort 约 5~9%，离地电气死区约 6%（见 [#deadband-bench](#deadband-bench)），
定点仍可能有 1~2cm 小晃（死区本征极限环，拧增益消不净；见 [理论 §7](balance_gain_theory.md#deadzone)）。
阶段 4 目标是小幅站住不跑飞；落地静摩擦的完整前馈留到阶段 5。

## 死区标定：命令与流程 {#deadband-bench}

对应 `config.h` 的 `kMotorDeadband[2]` / `kMotorCmdEps`，实现在 `WheelActuator::applyRawPwm`。

### 两种死区，别混 {#deadband-kinds}

| 种类 | 在哪测 | 填哪里 |
| --- | --- | --- |
| **电气/机械启动门槛**（驱动+电机） | **轮子离地 / 架空** | `kMotorDeadband` |
| **落地静摩擦**（体重+轮胎） | 平地承重 | 阶段 5 再补；**不要**整数值填进 `kMotorDeadband` |

填 `kMotorDeadband` 只用离地值；平衡效果在平地验证。

### 前置（必做）{#deadband-prep}

1. 车架空，两轮悬空，可自由转。
2. **暂时关掉死区前馈再测**——否则 `e` 经 `WheelActuator` 已被抬高，测到的不是真门槛：

```cpp
// include/config.h 临时改成：
constexpr float kMotorDeadband[2] = {0.0f, 0.0f};
```

烧录后再测。测完再按公式写回。

3. 用串口桥（或 monitor）盯遥测里的 `v=L/R`（左/右轮速）：

```bash
# 终端 A
~/.platformio/penv/bin/python3 tools/stage2_serial_bridge.py -l logs/deadband.log
# 终端 B
echo 'm 0' > /tmp/fishbot_cmd
```

### 流程 A：离地测启动门槛 {#deadband-air}

```text
m 0          # 开环
s            # 确认停住（effort=0）
el 2         # 只动左轮，从很小开始，每档停 1~2s，看 v=L/...
el 3
el 4
...
el 0         # 左轮测完清零
er 2         # 只动右轮，同样往上加，看 v=.../R
er 3
...
er 0
e 0          # 或 s：左右都清零
```

命令：

| 命令 | 作用 |
| --- | --- |
| `e <duty>` | 左右轮同设开环占空比 |
| `el <duty>` | **只左轮** |
| `er <duty>` | **只右轮** |

判据：**不用手拨、该轮能持续转**的最小 `|el|` / `|er|`，就是该轮正转门槛 \(D_+\)。

- 反转同样测：`el -2`、`el -3`… / `er -2`…
- 同一轮取 \(D=\max(|D_+|,|D_-|)\)（或正反分别记，先用较大值）。

| 轮 | \(D_+\) (%) | \(D_-\) (%) | 取用 \(D\) | \(0.65\times D\)（建议填） |
| --- | ---: | ---: | ---: | ---: |
| L (`el`) | | | | |
| R (`er`) | | | | |

> **平衡模式下左右死区务必先填相同值。** 左右差 >1% 时，同一 `desired` 经前馈后
> 两轮出力不同 → 差速撕平衡，表现为「一开死区就站不住」。分填只在开环标定后、
> 且确认同值能站稳，再做小幅微调。

### 怎么填回 config {#deadband-fill}

取实测门槛的 **60~70%**，别填满（填满易在平衡点嗡鸣）。**先左右同值验证能站**，再微调：

```cpp
constexpr float kMotorDeadband[2] = {4.0f, 4.0f}; // 例：门槛约 6 → 0.65*6≈4；先同值
constexpr float kMotorCmdEps      = 0.5f;  // 太嗡可试 1.0~1.5
```

本车参考：离地门槛约 **6%** → 起步 `{4,4}`。左右门槛差大时，仍建议先用较大一侧的 65%，
同值两边填；确认平衡不散后再各自微调 ±0.5。

### 流程 B：验证（先离地感观，再平地平衡）{#deadband-verify}

1. 写回 `kMotorDeadband` 后烧录。
2. **开环粗验（仍可架空）**：`m 0`，`e 1` 左右——前馈打开后，很小的 `e` 也可能推动；属预期。
3. **平衡验（平地）**：

```text
m 1
w 0
y 0
# 可选：t <实测稳态 pitch> 把 trim 对齐
```

- [ ] 能稳站、不持续嗡鸣 / chatter
- [ ] 若嗡鸣：降 `kMotorDeadband`，或把 `kMotorCmdEps` 提到 1.0~1.5
- [ ] 若定点发软、小偏置推不动：略升 `kMotorDeadband`（仍 ≤ 实测门槛）

### 可选：平地对照（不填进 config）{#deadband-ground}

想知道落地门槛大概高多少：平地、`m 0`，同样从小加 `e`，记「整车刚能动」的值。
这个数通常 **>** 离地值，只作参考，**不要**直接当 `kMotorDeadband`。
