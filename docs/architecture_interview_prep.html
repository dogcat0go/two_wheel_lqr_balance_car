运控岗补课 · 架构篇 · 配合 ROS2 / VMC 篇

运控软件架构：一页纸、情景题答案与小 demo 规格

JD 原话：「梳理模块边界、接口定义、数据流与控制模式切换机制」。这四个词就是全部考纲。本篇把你的平衡车按这四个词重新整理成可打开讲的材料，给出高频情景题的标准答案，并规定一个几百行、无 ROS 依赖的小 demo 让答案有东西可指。

0. 他们说的「架构」是什么，不是什么

是不是
分层与越界禁令：谁可以写执行器、谁不许依赖 ROS类图、设计模式名词
Schema：State / Command / Mode 的字段、单位、时间戳、版本UML 建模工具熟练度
数据流：多速率衔接、过期规则、单 writer、无锁交换微服务 / DDD
模式切换：状态机 + 仲裁 + 终裁权 + 力矩衔接把「切换」理解为换一个 PID 参数集
演进：加算法 / 换板 / 加传感器时核心不改，怎么保证一次性画一张宏大目标图

判断标准只有一条：加 RL、换 MCU、多一个传感器时，调度层与安全层不改。面试所有情景题都在测这一条。

本篇的用法

第 1–5 节是「材料」：面试时可以打开或默画。第 6 节是「答案」：按情景题背骨架，不背句子。第 8–9 节是「证据」：做一个小 demo，让第 6 节每个答案都能指到一行代码或一条日志。

讲这张图时按「频率 → 边界 → 权限」三句话：

  1. 频率：200 Hz 硬周期只在 Core1；Core0 与上位机都是软频率。
  2. 边界：两核之间只有 ControlSnapshot 和 CommandInput 两个 POD，临界区只拷一个结构体。换通信层（串口 → micro-ROS）控制环零改动——这是已经发生过的事实，不是设想。
  3. 权限：控制律只产 \(\tau\) 请求；Safety 是执行器前唯一闸门；上位机断链只能让速度归零，不能让车倒。

2. Schema：State / Command / Mode 现状与缺口

面试里「接口定义」= 你能不能把结构体讲成契约。现状照实说，缺口主动说。

2.1 现状

方向结构体关键字段契约
控制 → 通信 ControlSnapshot stamp_ms、pitch/yaw/轮速、tau_nm[2]、effort[2]、fault 位掩码、mode、armed、ctrl_hz、overrun_count 单 writer（Core1）；SI 单位；只在 ROS 消息边界换算
通信 → 控制 CommandInput stamp_ms、linear_x/angular_z、mode、lqr_gains[4]、reset_seq、calib_seq、坡角注入 stamp 过期 → kCmdTimeout；*_seq 递增即触发一次，不是电平
模式 uint8_t mode 0 开环 · 1 PWM 平衡 · 2 电流手调 · 3 电流+LQR 切换当拍 reset() 全部积分与参考
故障 Safety::Fault kFall | kImuLost（硬，锁存）· kCmdTimeout（软） 硬故障切电机需人工 r；软故障只清 \(v,\omega\)

值得点名的两个设计：reset_seq 用序号而不是布尔——避免「上位机还没来得及清位就被控制环反复消费」；cmd_stamp_ms==0 视为尚未收到指令、不判超时——避免上电竞态误锁。这是接口定义里的细节，面试官爱听。

两条硬规则，面试原句：

  1. 单 writer：同一拍只有一个模块产生 \(\tau^*\)；切换先改模式再改 writer；禁止两个律相加当「平滑」。
  2. 双机模式机：上位机跑完整 FSM 给算法看；MCU 只认识 Damping / 闭环 / Fault，非法模式或超时自己回退，不听上位机。

4. 三条越界禁令（回答任何「能不能」的底牌）

  1. 策略 / 感知 / 规划不直写关节。只能产生指令进仲裁层。视觉丢帧、Nav2 停、RL 崩，都只是指令源消失。
  2. ROS2 / DDS / WiFi 不进平衡回路。相位账：\(\omega\approx15\,\mathrm{rad/s}\) 时 20 ms 即 \(17^\circ\)，超过该构型裕度上限。回路在 MCU。
  3. 软故障不改模式。断链、超时、丢帧只清参考；只有摔倒 / IMU / 驱动器错误改模式并锁存。

被问到任何「X 能不能直接 Y」，先对照这三条；违反即回答「不能，因为第 n 条」，再给替代路径。

6. 情景题与标准答案

背骨架不背句子。每题结构：先说禁令 / 边界 → 改哪 → 不改哪 → 怎么验证。

6.1 「现在要接一个 RL 策略，哪些改、哪些绝对不改？」

标准答案

改：(1) 新增一个 writer：PolicyAdapter，把 State 拼成 obs、把 action 转成 Command；(2) 模式机加 PolicyWalk 一格和两条转移；(3) 仲裁层加一条规则：PolicyWalk 时 writer = 策略，其它模式 writer = LQR；(4) 心跳与合法性检查（超时、NaN、幅值）。

不改：Safety 闸门、MCU 协议与 Schema 语义（最多加字段并升版本）、LQR 本身、执行器层、200 Hz 调度。

验证：杀掉策略进程，日志里 writer 当拍切回 LQR，\(\tau\) 连续无阶跃；Fault 触发时策略无法把车拉回 PolicyWalk。

考点：扩展点是否在仲裁层而不是塞进 LQR；安全终裁是否独立于策略。

6.2 「策略进程崩了，这一拍力矩谁写？下一拍呢？」

标准答案

这一拍：仲裁层看到心跳过期（或读到旧 seq），writer 立刻置为 LQR；LQR 从上一拍实际输出的 \(\tau\) 开始按斜率衔接，不是从 0 起。模式回 Balance，不进 Fault——这是软故障。

下一拍及以后：\(v^*=\omega^*=0\) 保持站立；策略重启后必须重新申请 PolicyWalk，且要 Balance 已稳、无硬故障才批准。禁止自动弹回。

再往下一层：即便编排器整机死掉，MCU 的 cmd 超时也会自己清速度继续站——两层兜底。

考点：单 writer、bumpless、软硬故障分级、MCU 终裁。

6.3 「仿真跑通的代码，上真机改哪几行？」

标准答案

目标是只换最底层：Transport（UDP/共享内存 → 串口/CAN）和 Plant（Gazebo/MuJoCo → 真电机）。算法进程只调 SDK/编排器 API，不感知后端。

诚实现状：我的仿真车节点扮演 MCU，真机则是固件；两边共用的是接口语义（状态字段、命令口径 \(v,\omega\)、超时清速度、硬故障锁存），不是同一份二进制。参数分别标定（质心高度差导致坡度放大比 1.05 vs 2.19 就是分开标出来的）。

怎么补：把编排器抽出来，仿真里接 SimAdapter 扮演 MCU（同 Schema、同安全子集），真机接串口；这样「改几行」变成「改配置里的 transport 类型」。

考点：分叉点在哪一层；是否诚实区分「接口一致」与「代码一致」。

6.4 「两个团队同时改 Command 结构体，怎么不打架？」

标准答案

(1) Schema 单一来源：一个头文件 / IDL，两板同一份，进版本控制并有 owner。(2) 帧内带 schema_version，握手时校验；不一致拒绝进入 Active，而不是运行到一半错解。(3) 只加不删、新字段有默认值；删字段升主版本。(4) 每拍命令与慢变配置分开，减少改动面。(5) CI 里跑一遍「旧版发、新版收」的兼容测试。

考点：接口契约意识；「不一致时拒绝启动」比「兼容一切」更实用。

6.5 「线程模型是什么？哪条路径不允许分配内存？」

标准答案

真机：两核两任务。Core1 control_task 200 Hz，vTaskDelayUntil 固定周期；Core0 comm_task 处理串口与 micro-ROS。二者只通过两个 POD 快照交换，portMUX 临界区内只做结构体拷贝；控制任务内无堆分配、无打印、无阻塞调用。曾试过用优先级压 WiFi/lwIP 压不住，最后靠双核物理隔离。

上位机编排器（rclcpp）：订阅回调在非实时线程写 RealtimeBuffer；周期任务无锁读、预分配帧缓冲、禁止日志和 new；service（切模式、清故障）放另一个回调组，避免在周期回调里同步调用死锁。

考点：能否把实时纪律说成结构性约束，而不是「我小心一点」。

6.6 「怎么做回归？改了控制律怎么知道没坏？」

标准答案

三层：(1) 单元级：纯函数模块（LQR、TwistRef、YawMixer、Safety）无硬件依赖，可在 PC 上喂序列对比输出。(2) 回放级：遥测日志作输入，重跑控制律比较 \(\tau\) 轨迹。(3) 系统级：自动化验收脚本，位置 / 航向 / 单轮里程 / 姿态漂移四项判据判「假稳定」——抓过一例遥测 244 s 稳定、实为静摩擦锁死且力矩单调发散。

架构上的前提：控制律不直接读硬件、不直接写 PWM，才能被回放。这也是为什么执行器与传感器要抽成 WheelActuator / WheelSensor。

考点：可测试性是架构决策的结果；有真实抓 bug 案例。

6.7 其余高频

「加一个新传感器（比如 VIO 位姿）进来，动哪里？」

进估计层，不进控制律：作为一路观测进 KF（你有多观测串行更新的现成结构），以协方差表达可信度；State Schema 加字段并升版本；过期帧按软故障处理（该路 R 拉大或跳过更新），控制律看到的仍是同一组状态。控制律、安全层、执行器不动。

「把 ESP32 换成 STM32，上层要改什么？」

理想：零。因为板间契约是 Schema + 帧协议，不是芯片。实际：WheelActuator / WheelSensor / Ahrs 底下的外设驱动换（MCPWM→TIM、PCNT→编码器模式、I2C 同），control_task 的周期机制换成 FreeRTOS 同名 API（本来就在用），上位机不知道换了板。这也是为什么外设要收在硬件边界层并在 config.h 吸收极性。

「为什么不直接用 ros2_control 做整套？」

它解决的是 Linux 上「硬件抽象 + 周期调度 + 控制器 claim」，我的固件是同构实现。不用它做平衡回路是因为回路必须在 MCU（相位账）；上层关节伺服或仿真侧可以用。产品的模式切换是策略与 LQR 的 writer 仲裁 + 故障态，比 switch_controllers 多一层语义，所以编排器要自己写，但可以复用它的 RealtimeBuffer 和生命周期思想。

「多速率怎么衔接？RL 50 Hz、内环 200 Hz。」

上位机指令带 stamp；MCU 每拍读最新值，零阶保持 + 斜率限幅（TwistRef 已经在做）；年龄超阈值当软故障。不做插值预测——预测错比保持旧值更危险。反向遥测降采样发，控制不等遥测。

「你设计里最想推翻的一个决定？」

把 mode 做成裸整数并让 Core0 直接决定它。应该是上位机申请、MCU批准；现在 MCU 只在硬故障时否决。demo 里改成 MCU 侧白名单 + 拒绝回退。第二个是每拍命令和增益混装。

7. 「大型软件项目」经历怎么翻译

你的大型系统经验是 OpenHarmony 网络子系统与 NewIP 协议栈，不是平衡车。面试要把它从「协议名单」翻成「架构语言」。

你做过的翻译成架构词一句话
Netlink 监听网卡事件 → 更新路由 / 防火墙；SA 服务经 IPC 提供增删改查 模块边界 + 接口契约 「内核事件面、系统服务面、JS 接口面三层，每层只通过固定接口穿越；C 只用于与内核 API 交互」
NewIP：用户态 AF_NINET 套接字 → 内核三元映射注册 fd → 邻居表 / 路由表状态机 分层协议栈、状态机、数据结构选型 「新增一种地址族而不改上层 socket API，靠的是协议族注册边界；邻居表状态机和轮足模式机是同一类东西」
perf / ftrace 定位协议栈开销，路由表 hash + 软件缓存 性能剖析 → 数据结构演进 「先量再改，和我后来做误差预算排序主导项是一个方法」
Vxworks ↔ OpenHarmony 软总线互通；1–5 ms 时钟同步 跨平台接口层、多机时基 「两套系统一份协议语义，对应现在仿真 / 真机一份 Schema」
DNS / DHCP / NTP 服务端跨 3.1 → 4.1 版本维护 接口兼容与演进 「版本升级时对外接口不变、内部实现替换，就是‘持续演进’」

控制在 60 秒内，然后主动转回运控：「这些经验让我在做平衡车时第一天就把两核边界和安全闸门定下来，而不是先写控制律。」

8.2 必须满足的行为（验收清单）

#场景期望对应答案
1正常站立writer = LQR，\(\tau\) 有界，模式 Balance基线
2策略申请 PolicyWalk，但 Balance 未稳拒绝，模式不变批准权在编排器
3已稳后申请当拍换 writer，\(\tau\) 无阶跃（斜率限内）bumpless
4策略心跳停 > 阈值下一拍 writer = LQR，模式 Balance，不进 Fault6.2
5策略输出 NaN / 超幅同 4，并记一次软故障计数合法性检查
6编排器整机停发帧MCU 侧自己 cmd 超时，\(v^*=0\) 继续闭环双层兜底
7推倒（pitch 超阈值）MCU 进 Fault，\(\tau=0\)，锁存；编排器发 PolicyWalk 被拒MCU 终裁
8clearFault 未扶正拒绝恢复条件
9clearFault 扶正后Observe，仍不出力；再武装才 Balance禁止自动弹回
10两边 SCHEMA_VERSION 不同握手失败，拒绝 activate，日志明确6.4
11帧 CRC 错 / seq 倒退丢弃，不更新命令；连续丢触发超时帧协议
12Loopback 换 UDP只改 main 里一行构造6.3

8.3 关键接口（只给签名，实现你写）

// schema.hpp
constexpr uint16_t SCHEMA_VERSION = 1;
enum class Mode : uint8_t { Observe, Balance, PolicyWalk, Fault };
enum Fault : uint8_t { kOk = 0, kFall = 1, kImuLost = 2, kCmdTimeout = 4 };

struct State   { uint32_t seq; uint64_t t_ns; float pitch, pitch_rate, pos, vel;
                 float tau_out[2]; Mode mode; uint8_t fault; };
struct Command { uint32_t seq; uint64_t t_ns; Mode mode_req; float v_ref, w_ref;
                 float tau_req[2]; uint8_t writer_id; };
struct Frame   { uint16_t version; uint8_t kind; uint8_t len; uint8_t payload[64]; uint16_t crc; };

// writers.hpp
struct IWriter {
  virtual void  reset(float tau0) = 0;              // bumpless 起点
  virtual float update(const State& s) = 0;         // 只产 tau 请求
  virtual bool  healthy(uint64_t now_ns) const = 0; // 心跳 / NaN / 幅值
  virtual ~IWriter() = default;
};

// orchestrator.hpp
class Orchestrator {
 public:
  void tick(uint64_t now_ns);           // 读 State → FSM → 仲裁 → 发 Command
  bool requestMode(Mode m);             // 外部申请，返回是否批准
  void clearFault();
 private:
  Mode      mode_;
  IWriter*  active_;                     // 同一拍唯一
  IWriter*  lqr_;  IWriter* policy_;
};

8.4 明确不要做的

  • 不要接真 ONNX / 神经网络。函数冒充 \(\pi\) 足够；考点是仲裁不是精度。
  • 不要上 ROS2。若之后想接，把 Orchestrator 包成一个 rclcpp 节点即可；demo 本体保持零依赖便于面试现场编译运行。
  • 不要做 GUI。CSV + 一张 matplotlib 图（\(\tau\) 与 writer / mode 随时间）就是全部可视化。
  • 不要写多于两个 writer、多于四个模式。

规模控制

Schema+CRC 约 80 行，Transport 约 60 行，Plant 约 60 行（直接抄仿真 A、B、K），MCU 侧约 120 行，Orchestrator 约 150 行，main 场景约 80 行。合计 500–600 行。超过 1000 行说明在做别的事。

9. 三分钟演示脚本

  1. （20 s）打开 schema.hpp：「两边同一份，带版本和 CRC。」
  2. （30 s）跑默认场景，指日志：writer 列从 lqr → policy，\(\tau\) 连续。「单 writer、bumpless。」
  3. （30 s）看 t=6 s 策略心跳停：writer 回 lqr，mode 仍 Balance。「软故障不换模式。」
  4. （30 s）t=9 s 推倒：mode Fault，\(\tau=0\)；随后策略申请被拒。「MCU 终裁，禁止自动弹回。」
  5. （30 s）改 SCHEMA_VERSION 重编一边：握手拒绝。「接口契约。」
  6. （20 s）把 Loopback 换 UDP 一行：行为不变。「分叉只在 Transport。」
  7. （20 s）收尾：「真机固件是这套的 MCU 半边，已经跑在 ESP32 上；缺的 PolicyWalk 就是这个 demo 补的。」

10. 闭卷自测

Q1 · 用四个词复述 JD 的「架构」，并各举你系统里一个对应物。

边界：shared_state.h；接口：CommandInput stamp/seq 语义；数据流：200 Hz 快照 + 名义周期；模式切换：armed/硬软故障分级。

Q2 · 三条越界禁令。

策略不直写关节；ROS2 不进回路；软故障不改模式。

Q3 · 策略崩了这一拍谁写、从哪个值起、模式变不变？

LQR；从上一拍实际 \(\tau\) 按斜率起；模式回 Balance 不进 Fault。

Q4 · reset_seq 为什么是序号不是布尔？stamp==0 为什么不判超时？

避免重复消费和竞态；避免上电尚未收到指令就误锁。

Q5 · Schema 不一致时应该怎样？

握手校验版本，不一致拒绝 activate；不要「尽力兼容」到一半错解。

Q6 · 为什么控制律能被回放测试？前提是哪条架构决策？

控制律不读硬件不写 PWM，通过 WheelSensor/WheelActuator 隔离。

Q7 · 换 MCU 上位机改什么？换通信层控制环改什么？

都应为零；后者在你仓库已发生（串口→micro-ROS）。

Q8 · 你自己最想推翻的决定。

Mode 裸整数由上位机直接决定；命令与配置混装。
