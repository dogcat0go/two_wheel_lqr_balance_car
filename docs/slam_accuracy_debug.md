# 建图不准的分诊与成熟方案

> 现象：SLAM 建出的地图有重影、错层、闭合不上。怀疑对象：IMU、轮式里程计、车轮打滑。
> 相关：[`imu_boot_calibration.md`](imu_boot_calibration.md)、[`ros2_runtime_perf_labs.md` §2.2](ros2_runtime_perf_labs.md)（三设备时间同步）

**核心判断：这三个嫌疑人造成的地图畸变特征不同，可以互相区分。不要一上来就调参或换传感器——先做四个能互相排除的实验，把根因锁死在一个上。**

---

## 1. 先排除三个"不是传感器"的原因

这三个问题伪装成"传感器不准"的能力极强，而且在本项目里**大概率都存在**。不先排除它们，后面所有标定都是在给错误的模型标参数。

| 嫌疑 | 为什么它像"IMU/里程计不准" | 怎么确认 |
| --- | --- | --- |
| **时间戳不同步** | scan 和 odom 不在同一时间轴，配准时用错了位姿。旋转 1 rad/s 时 10 ms 误差 = 0.57°，3 m 处 3 cm | 见 [runtime 文档 §2.2](ros2_runtime_perf_labs.md)。**特征：静止时地图完美，一转就糊** |
| **scan 丢帧** | micro-ROS MTU 1024 而 360 点 LaserScan 有 1440+ 字节，被切片后 best-effort 下任一片丢失整帧就废 | `ros2 topic hz /scan` 对比雷达标称频率；序号缺口统计 |
| **扫描未去畸变** | 一圈扫 100 ms，运动中一帧 scan 沿轨迹拉开，墙面被扫成弧线 | **特征：误差与速度成正比，停下就没有** |

> 三者的共同特征是**误差与运动速度相关、静止时消失**。如果你的地图在车静止时也糊，那才轮到怀疑传感器本身。

## 2. 四个能互相区分的实验

按顺序做，每一个都能砍掉一半的可能性。

### 实验 1：静止建图 5 分钟

车完全不动，看地图会不会自己糊。

- **糊了** → 与 odom / IMU / 打滑全都无关。去查雷达噪声、`slam_toolbox` 的 scan matcher 参数、或者环境里有移动物体。
- **没糊** → 继续下一个。

### 实验 2：手推直线（不通电）

断掉电机，手推车走一条直线，全程贴墙走。这一步**同时排除了打滑和电机噪声**。

- 地图直线段是弯的 → 时间戳或去畸变问题（回第 1 节）。
- 直线是直的但**长度不对** → 轮径标定错（`m_per_tick`）。这是系统误差，可重复、有固定符号。

### 实验 3：原地旋转 360° 回到原位

差速车最考验同步与航向的动作。

- 墙面出现重影 → 时间戳 / 去畸变 / 航向源问题。
- 转一圈后**角度闭合差固定** → 轮距（`track`）标定错，或航向源有系统偏差。
- 闭合差每次不一样 → 打滑或 IMU 噪声。

### 实验 4：二分法——把 odom 摘掉

让 SLAM 只靠激光。`slam_toolbox` 的 scan matcher 本来就不强依赖 odom，odom 只是给初值；也可以拿 `rf2o_laser_odometry` 之类做纯激光里程计当对照。

- **摘掉 odom 反而更好** → **odom 在拖后腿**，问题在里程计或航向源，不在雷达。
- 一样差 → 问题在 scan 侧。

这一步是整套分诊里最快的一刀，建议提前做。

## 3. 本项目里已经存在的一个具体问题

`lib/Ahrs/Ahrs.h` 开头写着：

> 航向角 ψ 用轮式里程计（Ahrs 不积分 yaw，避免陀螺漂移当 heading hold 参考）。

`Kinematics::update_odometry` 也确实是从左右轮速反解 `angular_speed` 再积分出 `theta`。

**这个选择对"航向保持"是合理的，对"建图"是最差的。** 两者的需求正好相反：

| 用途 | 需要什么 | 轮速差航向 | 陀螺航向 |
| --- | --- | --- | --- |
| 航向保持（控制） | 相对参考稳定、无长期漂移 | 合适 | 漂移会让参考跑掉 |
| **建图（估计）** | **短期角速度准确** | **打滑时完全错，且错误不可恢复** | 短期极准，长期漂移由回环吃掉 |

打滑时轮速差算出来的角速度是纯粹的错误信息，而陀螺照样准。SLAM 的回环检测本来就是用来消化陀螺慢漂移的——**把陀螺的长期漂移交给回环，把打滑的瞬时错误挡在外面**，这才是正确的分工。

所以第一件该改的事：**建图链路上的 yaw 改用陀螺，轮速只提供前向速度。** 控制侧的 heading hold 可以继续用原来那套，两者不冲突（它们本来就服务于不同目的）。

## 4. 成熟方案清单

### 4.1 融合：`robot_localization`（这就是标准答案）

ROS 生态里融合轮式里程计与 IMU 的标准包，用 EKF/UKF 输出 `odom → base_link`。

配置上最重要的一条经验，正好对应第 3 节：

- **`odom0_config` 只开 `vx`**，把 yaw 和 vyaw 全部关掉；
- **`imu0_config` 提供 yaw / vyaw**；
- 平面机器人开 `two_d_mode: true`。

这样打滑时轮子空转只会污染速度估计（且很快被修正），不会污染航向——而航向错误才是地图畸变的主因。

另一个常被忽略的点：**协方差必须填真实值**。很多实现里 odom 消息的 covariance 是全 0 或随手填的常数，EKF 于是按错误的权重融合，加了滤波器反而更差。协方差就是你告诉滤波器"这个数据有多可信"的唯一渠道。

### 4.2 标定：先把系统误差标掉，别让滤波器去背

| 对象 | 方法 | 产出 |
| --- | --- | --- |
| 轮径 / 轮距 | **UMBmark**（Borenstein & Feng）：正方形路径顺时针、逆时针各跑若干圈，测终点偏差 | 能**分离**轮径比例误差和轮距误差这两个分量，这是它比"走直线量一下"强的地方 |
| IMU 噪声 | `allan_variance_ros` / `imu_utils`，静置采集数小时算 Allan 方差 | 陀螺/加速度计的噪声密度与随机游走，直接喂给 EKF 的过程噪声 |
| IMU 零偏 | 已有实现，见 [`imu_boot_calibration.md`](imu_boot_calibration.md) | 上电零偏 |

系统误差（标定问题）和随机误差（噪声问题）要分开治：**滤波器只能处理随机误差，系统误差喂进去只会被当成真值积累。**

### 4.3 打滑检测：两个判据，因为它们各有盲区

**差动打滑**（单轮空转、原地打转）用陀螺对照轮速差就能抓：

```
|ω_陀螺 − (v_右 − v_left)/track| > 阈值   →  差动打滑
```

但这条判据有一个盲区：**两轮同时打滑时它完全失效**。地面很滑、猛加速、或者车顶着墙推——陀螺说"没转"，轮速差也说"没转"，两者一致，判据不报警，而车其实根本没往前走。这类共模打滑对里程计的破坏一点不小。

补上这个盲区要靠电机电流：

```
电流低 + 轮速高       →  轮子空转（失去负载）
电流高 + 轮速接近零   →  堵转 / 顶住障碍
```

两条判据是互补的：陀螺对照抓差动，电流抓共模与堵转。加速度计理论上也能抓共模（轮速说在加速、加速度计说没有），但在运动的车上噪声太大，不如电流直接。

检出后**不要停机，而是动态放大 odom 消息里的协方差**，让 EKF 自动降低对轮速的信任。这比"检测到打滑就丢弃数据"更平滑，也更符合滤波器的工作方式。

### 4.4 SLAM 前端

- **`slam_toolbox`**：`do_loop_closing` 打开，回环能吃掉航向慢漂移。`minimum_travel_distance` / `minimum_travel_heading` 控制关键帧密度——太大则约束不足，太小则图膨胀。
- **`cartographer`**：内建 IMU 紧耦合与扫描去畸变（`use_imu_data`），如果你不想自己实现去畸变，它是现成的。代价是配置复杂度高一截。
- **纯激光里程计**（`rf2o_laser_odometry`）：主要价值是当实验 4 的对照组。

## 5. 如果建图底盘就是这台平衡车

两轮平衡车（TWIP）的轮式里程计有一个普通差速车没有的问题：**车身俯仰会污染里程计**。

- 编码器测的是轮子相对车体的转角，而车体一直在前后倾；轮子转过的角度不等于车体在地面上走过的距离，两者差一个俯仰角项。
- 更麻烦的是平衡车必须持续微调，轮子一直在小幅前后摆动，这会给里程计注入**高频噪声**——即使车看起来停着不动。

两个应对：用 pitch 对轮式位移做补偿；或者干脆降低 odom 权重、更多依赖 scan matching（回到第 4.1 的思路）。建图时如果能用一台静稳的三轮/四轮底盘，会省掉一大堆麻烦——**平衡车做 SLAM 平台，是在给自己增加一个不必要的难度维度。**

## 6. 建议的动作顺序

1. **排除时间同步与丢帧**（第 1 节）。这两项在本项目里大概率存在，不修的话后面全是白干。
2. **做实验 4**（摘掉 odom）。一刀砍掉一半可能性，成本极低。
3. **把建图链路的 yaw 换成陀螺**（第 3 节）。这是单点收益最大的一改。
4. **UMBmark 标定轮径与轮距**（第 4.2）。把系统误差清掉。
5. **接 `robot_localization`**（第 4.1），协方差填真实值。
6. 还不够再上打滑检测与自适应协方差（第 4.3）。

前三步不花钱、不加硬件，且大概率已经能解决大部分问题。
